# D-20260728-02 — One portable recorder serves Codex and Claude

Index: [DecisionHistory.md](../DecisionHistory.md)

## Detail

### Objective

Turn the delivery-efficiency policy into an installable recorder for Codex and
Claude Code without creating two incomparable stores, depending on an agent to
remember manual timestamps, or claiming platform behavior that was not tested.

### Selected boundary

`tools/delivery-efficiency/` is a repository-owned runtime tool, not a sixth
skill. A skill is loaded after the runtime has already received a request and
started model work, so it cannot own the required receipt-to-delivery boundary.
The existing canonical skill installer also relies on POSIX locks, directory
descriptors, and direct symlinks and therefore cannot serve as a native Windows
runtime installer.

The tool has one Python 3.9-compatible standard-library core. That core alone
owns the exact event schema, HMAC-derived opaque identities, privacy allowlist,
receiver clock, SQLite WAL spool, crash-safe UTF-8/LF JSONL projection, status,
and install transaction. Codex and Claude adapters only translate runtime
events into the same published, versioned adapter contract. Each durable
schema version is immutable; a compatible reader may accept supported older
rows alongside current rows, but an adapter must not introduce a second ledger
writer, private schema, or state store.

Installation copies a hash-bound version into the user-state directory instead
of executing mutable checkout files or requiring symlink privileges. Native
Windows, WSL, Linux, and macOS installations use their own local-filesystem
state. In particular, WSL state remains inside its Linux filesystem and is not
shared with native Windows through `/mnt/c` or `\\wsl$`; compatible JSONL
schemas permit later offline aggregation without concurrent cross-kernel
SQLite access.

Codex uses complementary sources. Lifecycle hooks provide task, tool, and
subagent boundaries but deliberately discard prompts, messages, transcripts,
working directories, tool payloads, and raw errors. Native OTLP/HTTP JSON adds
authoritative response token categories with `log_user_prompt = false`. A
controlled `codex exec --json` wrapper provides the strongest receipt, stream,
usage, process-exit, and output-delivery boundary for non-interactive runs.
Hooks and telemetry each report partial coverage where the host does not expose
the exact boundary; a turn stop is not relabeled as proven completed scope.

Claude Code Fable at max effort owns the Claude-specific translator design. It
must emit the same adapter schema and use the shared recorder core. This keeps
runtime-specific discovery with the runtime requested by the user while the
repository remains universal.

### Storage and privacy

Each environment uses a local SQLite WAL spool with `synchronous=FULL` and a
serialized, fsynced `EfficiencyLedger.jsonl` projection outside source
worktrees. Stable source keys deduplicate retries. Recovery accepts only the
expected complete pending event after an append-before-commit crash, truncates
only a partial uncommitted suffix, and fails closed on unexpected complete
history. It never rewrites confirmed events.

The durable schema has no arbitrary source payload. Prompt and assistant text,
source and transcript content, working paths, filenames, commands, tool
arguments and results, raw errors, secrets, account data, and personal data are
excluded by a positive allowlist. Source identifiers exist only in adapter
memory or one authenticated loopback handoff and become installation-keyed
opaque IDs before any persistence. Unknown
counters remain null; zero is accepted only from an authoritative zero.

### Platform contract

- Windows: `%LOCALAPPDATA%\\HolySkills\\DeliveryEfficiency`
- macOS: `~/Library/Application Support/HolySkills/DeliveryEfficiency`
- Linux: `${XDG_STATE_HOME:-~/.local/state}/holyskills/delivery-efficiency`
- WSL: the Linux location on the WSL filesystem, never a Windows-mounted path

The runtime uses argument-vector subprocesses internally, an absolute selected
Python executable, both Codex `command` and `commandWindows`, SQLite rather
than POSIX file locks, and same-directory namespace mutations. Native platform
acceptance remains distinct from simulated branch tests; unavailable native
evidence is reported as pending.

The recorder's state-root lock serializes cooperating installer processes.
The caller-reviewed immutable plan digest, directory identities, and target
digests are checked before mutation. Each change is a journaled move-only state
machine with deterministic adjacent stage, prior, and recovery slots. Existing
targets move no-replace to the prior slot before the reviewed stage moves
no-replace to the vacant target, so the target can be briefly absent but no
occupant is overwritten. Linux and WSL use `renameat2` no-replace, macOS uses
`renamex_np` exclusive rename, and Windows keeps the exact top-level stage
handle through `SetFileInformationByHandle(FileRenameInfo)` publication with
`ReplaceIfExists = FALSE`; its destination volume/file ID is checked before the
handle is released. Other Windows slot moves use `MoveFileExW` without
replacement. Rollback uses the same adjacent no-replace protocol, never
path-unlinks a mutable target, and retains unexpected occupants and artifacts.
If a filesystem lacks the required primitive, installation fails closed.

The unconditional integrity boundary covers managed target namespace
occupants and exact top-level stage identity. Random stage internals and
private transaction metadata are cooperative per-user state protected by the
account ACL, single-link lock files, and digests; hostile same-account content
mutation is outside that integrity boundary and is not presented as prevented.
Deterministic syscall-boundary and recovery fixtures cover parent swaps,
destination collisions, interruption after publication, detached transaction
recovery on POSIX, and native Windows file/directory handle publication.
