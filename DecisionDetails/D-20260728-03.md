# D-20260728-03 — Claude telemetry uses prompt-correlated hooks and OTLP logs

Index: [DecisionHistory.md](../DecisionHistory.md)

## Detail

### Objective

Give Claude Code the same delivery-efficiency recording as Codex through the
shared recorder core and versioned adapter contract, without inventing task
boundaries the host does not expose, weakening the privacy allowlist, or
creating a second store, schema, or ledger writer.

### Selected sources

The `claude-runtime` adapter translates two complementary Claude Code sources:

- The adapter recognizes lifecycle hooks (`SessionStart`, `SessionEnd`,
  `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`,
  `SubagentStart`, `SubagentStop`, `Stop`, `StopFailure`, and
  `MessageDisplay`) and records only the boundary each hook can establish.
  `UserPromptSubmit` supplies a partial request boundary; supported per-tool
  hooks can supply tool spans; `MessageDisplay` can establish first activity;
  and `StopFailure` can establish that a turn stopped. `SubagentStart` records
  first activity when applicable plus a coverage gap, while `SubagentStop`
  records a coverage gap. These two hooks preserve only partial presence and
  opaque per-instance identity: they do not establish a measured subagent
  lifetime or activity interval. Hook payload content — prompt text,
  transcripts, working
  directories, tool arguments and results, permission modes, compaction
  instructions, and notification text — is discarded by a positive allowlist
  before anything crosses the adapter boundary. `PreCompact` and
  `Notification` are recognized and deliberately translate to nothing because
  the current schema assigns them no efficiency semantics and compaction must
  never create a new task or lineage. The managed low-overhead hook set omits
  per-tool, session-end, and display hooks; those translations are defensive
  fallback for another supported source path.
- Claude Code's opt-in OpenTelemetry log export delivers correlated
  `claude_code.user_prompt`, `api_request`, `api_error`, `tool_result`, and
  `tool_decision` records over
  OTLP/HTTP JSON to the existing
  authenticated loopback `/v1/logs` endpoint, which now routes both Codex and
  Claude shapes. Only the runtime/session/prompt correlation and allowlisted
  counters cross the boundary: `input_tokens` and `output_tokens` map directly,
  `cache_read_tokens` maps to `cached_input`, and `cache_creation_tokens`
  maps to `other` because the schema has no cache-write category. Anthropic
  reports no separate reasoning or tool token category, so those stay null.
  A `user_prompt` supplies a content-free task boundary; its prompt text and
  length remain excluded. Native durations and outcomes cross only as bounded
  typed values. `tool_result`, `tool_decision`, and `api_error` content plus all
  account, organization, model, cost, and terminal attributes are ignored
  wholesale.

### Prompt-correlated task identity

Codex hooks carry a `turn_id`, so each Codex turn is a task. Claude Code hook
payloads in supported current hosts also expose UUID-v4 `prompt_id`, which is
the same value as OTLP `prompt.id` for `user_prompt`, `api_request`, and related
events. The initial session-generation design was based on an incomplete
reading of the host contract and is no longer the default.

Selected: hook `prompt_id` is the authoritative transient task/turn key and
OTLP `prompt.id` is an exact usage-correlation candidate. The core combines
runtime family, session, and task/turn source identity under installation-keyed
HMAC domains before persistence, so identical raw values from Codex and Claude
cannot share tasks. `user_prompt` and hook task starts collapse atomically by
that exact identity even when OTLP arrives first. Usage binds only to a matching
prompt task; it remains session-scoped when prompt correlation is missing,
malformed, changed, or has no matching boundary, and exact correlation remains
valid after Stop or an agent terminal declaration. Deterministic session-task
generations remain only as explicitly partial, collision-safe fallback for a
legacy payload with no prompt id.

`SessionStart` exchanges its raw session id in one authenticated loopback
request for a signed, installation-local opaque declaration handle. Only that
handle and the stable launcher enter Claude session context. Later declaration
processes validate the handle's signature, runtime family, observation match,
and task under the receiver transaction; a raw session id is never serialized
into the transcript-facing context. The receiver resolves that task once for a
whole declaration command, task-scopes every dedupe key, validates completion,
and commits the batch atomically. Concurrent prompts therefore cannot split a
requirement from its terminal, conflicts leave no batch prefix, an exact
terminal replay remains idempotent, and a repeated declaration shape on a later
task remains distinct.

The signed handle authenticates a request to the local recorder. It does not
authorize the agent to perform any action beyond the user's request.

### Installation targets

Claude Code v2.1.212 is the compatibility floor. Hook `prompt_id` correlation
exists from v2.1.196, but that alone is insufficient: Anthropic records
v2.1.212 as the release that fixed OTLP/HTTP export to endpoints which reject
chunked transfer encoding. The recorder deliberately rejects chunked request
bodies, so v2.1.211 and earlier cannot be represented as covered.

An explicitly named Claude home is a directory whose `settings.json` receives
managed handlers for `SessionStart`, `UserPromptSubmit`, `SubagentStart`,
`SubagentStop`, `Stop`, and `StopFailure`, plus a managed
telemetry environment block: `CLAUDE_CODE_ENABLE_TELEMETRY`,
`OTEL_LOGS_EXPORTER=otlp`, `OTEL_METRICS_EXPORTER=none`,
`OTEL_TRACES_EXPORTER=none`, explicit false values for tracing and every
prompt, assistant, tool-detail, tool-content, and raw-body gate, false values
for account/session/resource metric attributes, the HTTP/JSON loopback logs
endpoint, and the authenticated header. Claude documents `0` or `false` as the
off values for ordinary boolean environment switches and `none` as the
disabled exporter. The same transactional
plan/apply/verify/rollback journal covers Codex and Claude homes with the same
digest binding, drift refusal, and exact-byte rollback. Claude handlers use
the documented shell-free `command` plus `args` execution form on every
platform, so executable and argument paths do not require POSIX, `cmd.exe`, or
PowerShell quoting. Any
existing user-owned `OTEL_*` or `CLAUDE_CODE_ENABLE_TELEMETRY` value that
differs from the managed block is a conflict and fails before mutation, the
same way an existing Codex `[otel]` table does; unrelated settings, hooks, and
environment values are preserved byte-for-byte in rollback. User settings
override inherited shell values, but Claude gives project, local, CLI, and
organization-managed scopes higher precedence. Those external scopes can
replace this user-level block or route host telemetry outside the recorder,
including raw bodies written directly to disk; the adapter allowlist cannot
protect a path it never receives. Such an override is an explicit external
privacy and instrumentation conflict, and an organization that needs a locked
destination must deploy the same selectors and gates through managed settings.

Hook and OTLP tool completions share the runtime's `tool_use_id` as their raw
span identity. Both durable observations remain available, while reporting
deduplicates equal same-span native durations and makes conflicts unknown.
These arithmetic runtime-native sums are separate from recorder-clock interval
unions and wall time and preserve measurement and attribution provenance.

### Verification

Adapter conformance lives in `claude_self_test.py`: current-host hook payload
and OTLP export fixtures with content and identifier canaries, low-cardinality
tool mapping, exact prompt dedupe, two sequential prompt tasks, late usage
after terminal/Stop, OTLP-before-hook ordering, malformed and mismatched
correlation, legacy fallback, same-value cross-runtime isolation, concurrent
hook/OTLP task-start collapse, same-span native-duration deduplication and
conflict handling, signed declaration-handle rejection, CLI
context/no-op/gap classification, and a loopback end-to-end flow from real
`recorder.py hook claude` subprocesses through the receiver to the verified
cold ledger. Shared core, installer, schema, and platform suites continue to
run unchanged plus Claude fixtures. The workflow defines native Windows,
Linux, and macOS jobs and a separately gated WSL job. Those definitions and
simulated platform branches are test plans, not evidence that a native job
ran; native coverage is established only by the result of a completed job on
that environment.

### Authoritative Claude sources

- [Claude Code v2.1.212 release notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.212)
  identify the first release with the non-chunked OTLP/HTTP export fix required
  by the recorder's bounded receiver.
- [Claude Code hooks reference](https://code.claude.com/docs/en/hooks)
  documents hook payloads and lifecycle semantics, the v2.1.196 availability
  and OTLP correlation of `prompt_id`, blocking behavior, and the shell-free
  `command` plus `args` execution form.
- [Claude Code monitoring](https://code.claude.com/docs/en/monitoring-usage)
  documents OTLP logs, correlation attributes, duration and token fields, and
  the content-export gates and their privacy consequences.
- [Claude Code authentication](https://code.claude.com/docs/en/authentication)
  documents provider credential types and storage. Provider authentication is
  distinct from user authorization, just as the recorder's loopback token
  authenticates a recorder request without expanding the agent's authority.

### Supersession

This decision implements the Claude boundary reserved by D-20260728-02 and
changes none of its measurement, privacy, storage, or platform contracts.
