# D-20260729-01 — One canonical global policy serves Codex and Claude

Index: [DecisionHistory.md](../DecisionHistory.md)

## Detail

### Context and scope

The repository already owned one canonical universal file at
`reference/codex-app-wide/AGENTS.md`. The known Codex global entries were direct
absolute links to it, but the active user-level Claude `CLAUDE.md` was an
independently editable regular file and had diverged. Root `CLAUDE.md` already
used one thin project-relative import for repository policy; this change adds
the universal-policy import first while keeping the file a thin importer.

This decision extends canonical deployment to explicit user-level Claude files.
It does not rewrite the historical D-20260712-01 detail or undo that decision's
Codex topology; it supersedes only the earlier result that left Claude
unchanged. It also keeps policy deployment independent from delivery telemetry:
a SessionStart hook should observe telemetry, not become the owner of policy
files or imply that activation permits unrelated work.

### Options and evidence

- Selected one repository source with thin runtime adapters. Codex and
  POSIX/WSL Claude consume direct absolute symlinks. Native Windows Claude may
  consume one deterministic absolute `@path` import line only when the operator
  explicitly selects that mode because direct symlink capability is
  unavailable.
- Rejected copied global files because the observed Claude copy had already
  drifted and future repository updates would require another synchronization
  protocol.
- Rejected a second canonical Claude policy because two writable policy sources
  can diverge semantically even if a copier is reliable.
- Rejected integrating this mutation into the recorder installer because
  telemetry configuration, instruction deployment, trust, and user authority
  are separate operational boundaries.

Anthropic documents that Claude Code loads user instructions from
`~/.claude/CLAUDE.md`, supports absolute and relative `@path` imports, accepts a
symlink when no Claude-specific content is needed, recommends imports on
Windows where symlinks require Administrator privileges or Developer Mode, and
may prompt on first use of an external import. It also states that CLAUDE.md is
behavioral context rather than an enforcement or permission layer:
<https://code.claude.com/docs/en/memory>.

### Transaction and safety contract

`scripts/manage_global_policy.py` implements a separate
plan/apply/verify/rollback workflow. Every target and transaction directory is
an explicit absolute path. The immutable plan records source identity and hash,
target and parent snapshots, exact desired topology, and fixed adjacent backup
and temporary names without recording prior policy contents. Apply and rollback
require the printed plan digest.

Every live move is adjacent and atomic-no-replace: Linux and WSL use
`renameat2(RENAME_NOREPLACE)`, macOS uses
`renameatx_np(RENAME_EXCL)`, and Windows uses `MoveFileExW` without
`MOVEFILE_REPLACE_EXISTING`. This prevents a late backup or destination
collision from being overwritten. Existing objects move rather than being
copied, preserving their inode/file identity and platform metadata for exact
rollback. The manager revalidates source, parent, target, backup, and temporary
state at mutation boundaries. Each operation locks and holds a no-follow
transaction directory, journals through that held directory on POSIX, and
revalidates it at journal and target-mutation boundaries; native Windows also
holds directory handles without delete sharing. Rollback preflights all targets,
captures an installed object to its owned temporary name before restoring the
prior target, and preserves drifted external objects rather than deleting them.
Because portable path APIs provide no atomic compare-and-delete operation, the
captured deployed object remains under its unique reviewed temporary name after
rollback and is reported for explicit operator cleanup rather than being
unsafely unlinked.
Multiple target files are recoverably transactional, not one globally atomic
cross-filesystem operation.

Codex remains direct-link-only. Native Windows Claude wrapper mode is an
explicit plan option and is never an automatic fallback. The wrapper is one
UTF-8/LF import line with a normalized drive-absolute forward-slash path. UNC
and control-character paths are rejected. Cross-platform fixtures prove exact
serialization, including spaces and Unicode, but do not claim that a simulated
path was loaded by native Claude. Runtime activation remains pending until a
new session and `/memory` or `InstructionsLoaded` evidence confirms the
canonical file; any first-use external-import approval remains the user's
separate choice.

### Verification

The repository self-test covers exact regular-file and raw-symlink rollback,
metadata retention, ordinary canonical updates after installation, source byte
and inode swaps, source and transaction symlinks, parent replacement, target
drift, hard links and unsupported objects, plan and path tampering, backup and
install boundary collisions, rollback-retention drift, a mid-apply transaction
directory swap, deterministic apply and rollback crash recovery at every durable
boundary (including missing and multi-entry rollback), partial multi-target
failure, all-target rollback refusal, concurrent stale plans, direct-link
failure without fallback, unrelated siblings, Windows path and PowerShell
serialization, and absence of positive
authorization wording. Repository validation and native Windows, Linux, macOS,
and optional WSL CI jobs run that test. A workflow definition or simulated
Windows path remains planned coverage until the corresponding native job
actually succeeds.
