# D-20260731-01 — Agent work uses complete evidence passes and bounded scope

Index: [DecisionHistory.md](../DecisionHistory.md)

## Detail

### Evidence and objective

The user reported two recurring costs: agents fixed the first non-critical test,
debug, or deployment gap and restarted the entire cycle before learning what the
rest of the pass would reveal; and the policy's unconditional preference against
under-engineering expanded work into migrations, preservation, hardening, and
infrastructure that neither the request nor the project environment needed.
A follow-up correction clarified that the resulting material-expansion gate was
still too weak: under-engineering must remain explicitly unacceptable, while
every potential expansion beyond the requested result or credible need must be
put to the user before the agent acts.

The configuration audit found related context costs. The canonical universal
policy was 23,696 bytes. In the inspected long Codex task it was supplied seven
times, the skills catalog five times, permissions four times, and environment
context six times; eleven compactions retained replacement payloads of roughly
84–99 KB. The current startup exposed 46 skill summaries, of which 34 had no
exact project-use evidence, and 153 nested tool endpoints, of which 139 had no
project-history reference. Claude's project file also imported the same
canonical policy already supplied by its user-level symlink, with no documented
same-path deduplication.

Observed output extremes were a 74,413-character Claude file read (roughly
18,600 text tokens), Codex text results plateauing near 40,200 characters
(roughly the 10,000-token host boundary), and a 2,052,998-character image data
URL returned twice. These are context-delivery measurements, not proof that
every serialized byte was charged as text tokens.

### Selected behavior

- A finite full test, debug, reproduction, audit, migration-rehearsal, or
  deployment cycle reaches its end after non-critical failures. Actionable gaps
  enter the active completion ledger; complete raw output stays in a cold
  artifact. Only risk of harm, data loss, shared-state corruption, evidence
  destruction, or invalid remaining results permits an early stop.
- After the evidence pass, findings are grouped by cause, guardrails and
  implementation are fixed as a batch, and the complete relevant cycle is run
  again. A usable safe test deployment may proceed with gaps disclosed and an
  explicitly incomplete status.
- The requested lifecycle still receives a sound production-grade foundation.
  Under-engineering the agreed result is unacceptable; implementation gaps are
  more serious and more punishable than reasonable over-engineering.
- That asymmetry never permits silent scope expansion. Before every potential
  over-engineering expansion beyond the requested result or credible project
  need, especially security, privacy, backup, migration, preservation, or
  data-safety work, the agent asks for explicit approval before acting. The
  question states the proposal; evidence, scenario, and likelihood; benefit;
  cost, complexity, and maintenance; risks of doing and not doing it;
  alternatives;
  reversibility; and a recommendation. Disposable test data and irrelevant
  cross-account hardening are not preserved by default.
- Agent-controlled context uses targeted reads, relevant capabilities, bounded
  summaries, and cold raw artifacts. Unchanged content already in live context
  is not reloaded without a concrete reason.
- Repository-audit workers start in fresh contexts. Codex uses
  `fork_turns="none"`; its selector label `Light` maps to runtime effort
  `low`. Each generated prompt carries the complete task and exact report path,
  workers write full results directly to cold artifacts, and parent context
  receives only a bounded filename/hash/byte/count receipt. Complete lead
  syntheses and verbose command output likewise remain in final-report and log
  artifacts; chat is an outcome and artifact index.
- `full-repo-audit` and `full-repo-test-coverage-audit` are explicit-only
  skills. Their exhaustive workflows cannot enter context through implicit
  matching; the user invokes them with `$full-repo-audit` or
  `$full-repo-test-coverage-audit`.
- The formal web verifier owns context-safe delivery in software. Its normal
  invocation creates unique external JSON and Markdown artifacts and emits only
  a bounded receipt naming them on success, findings, coverage failure, and
  setup failure. Full Markdown stdout requires an explicit attended-human flag;
  an agent does not need to remember a quiet flag.
- The universal policy is compressed without a numeric word limit. The semantic
  checker enforces outcome-bearing contracts rather than preserving verbose
  wording. Root `CLAUDE.md` imports only root `AGENTS.md`; the user-level Claude
  target remains the single global consumer of the canonical universal policy.
  If that global policy is not loaded, project memory requires a direct
  session-local read of the canonical file and reports the activation gap.

### Alternatives and boundaries

- Fail fast is correct for harm, destructive state, or invalid evidence, but
  applying it to ordinary independent failures loses diagnostic coverage and
  repeats setup.
- Fixing every gap only after all work is complete would delay cheap focused
  feedback too far. Focused checks remain useful between the baseline and final
  full pass; they do not replace either full pass.
- Making under-engineering and over-engineering symmetric could encourage weak
  foundations. The selected rule keeps the asymmetry while requiring an
  informed user decision for every potential expansion beyond agreed scope or
  credible need; a material-only gate leaves smaller silent expansions open.
- Leaving exhaustive audits implicitly selectable would keep their metadata in
  routine context and permit accidental high-cost runs. Narrower trigger prose
  was rejected in favor of explicit-only activation because the intended use
  is deliberate and already has stable `$skill-name` entry points.
- Keeping context safety behind an optional receipt flag was rejected because a
  forgotten flag printed the complete formal report. Safe artifact-first output
  is now the default; explicit human-readable stdout preserves attended
  terminal use without weakening agent runs.
- A fixed universal token or word ceiling could remove necessary meaning. The
  selected approach instead removes duplication and requires relevance, which
  preserves D-20260714-01's rejection of arbitrary numeric document limits.
- Editing every runtime plugin profile during this change would be another
  unrequested expansion. The audit reports unused capability evidence and
  recommends project scoping or lazy exposure, but runtime profile mutation
  remains a separate informed choice.

This decision supersedes D-20260729-01 only where that decision described root
`CLAUDE.md` as importing universal policy again. Its canonical global source,
deployment topology, transaction, and activation requirements remain in force.
