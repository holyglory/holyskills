# D-20260731-02 — Security controls use user-confirmed project assumptions

Index: [DecisionHistory.md](../DecisionHistory.md)

## Detail

### Evidence and objective

The user corrected a recurring pattern in which agents applied generic maximum
hardening without establishing the project's users, environment, assets,
credible threats, trust boundaries, or accepted risks. The existing
every-expansion approval rule prevents silent extra scope, but it does not
establish the factual basis for security controls already requested or credibly
in scope.

### Selected behavior

- Project-root `security-assumptions.md` is the durable basis for every decision
  that adds, changes, weakens, removes, or intentionally omits a
  security-posture control.
- Read-only discovery may identify the questions, but before implementation
  read the file and cite the confirmed assumptions supporting the decision.
- If the file is absent, question the user about the full baseline: users and
  operators, environment and ownership, assets and data sensitivity, credible
  adversaries and misuse, trust boundaries, required gates, explicitly
  unnecessary gates, acceptable risks, and review triggers. If it exists but is
  insufficient, ask only the unresolved assumptions material to the current
  decision. Record confirmed answers before implementation; keep unknowns
  explicit and never use them to justify a control.
- Never invent assumptions, treat generic threats as project facts, or default
  to maximum hardening.
- Requested or in-scope security work does not bypass this gate.
- This gate and D-20260731-01 are cumulative. Assumption support does not
  authorize an expansion; a potential expansion still needs D-20260731-01's
  informative question and explicit approval. Conversely, expansion approval
  does not replace documented security assumptions. One user interaction may
  satisfy both only when it explicitly completes both contracts.

### Alternatives and boundaries

- Unconditional maximum hardening was rejected because it creates irrelevant
  cost and gates.
- Agent-inferred assumptions were rejected because they substitute speculation
  for user context.
- Applying the rule only to expansions was rejected because requested controls
  can also be disproportionate or based on false premises.
- Conversation-only assumptions were rejected because they are not durable
  across agents and tasks.

This decision complements and does not supersede D-20260731-01.
