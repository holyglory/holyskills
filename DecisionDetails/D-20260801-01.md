# D-20260801-01 — UI implementation audit requires explicit user invocation

Index: [DecisionHistory.md](../DecisionHistory.md)

## Detail

### Evidence and objective

The two full-repository audit skills were already explicit-only because their
exhaustive queues, workers, evidence, and reports are costly and can add large
amounts of context. The implemented-UI audit has the same operating shape but
remained eligible for implicit matching. The user required that it run only
after an explicit request.

### Selected behavior

- `ui-implementation-audit` requires deliberate invocation by direct runtime
  command: `$ui-implementation-audit` in Codex or
  `/ui-implementation-audit` in Claude Code.
- Ordinary implementation, UI work, review, testing, visual verification, or
  gap-finding language never activates this exhaustive workflow.
- Its canonical `SKILL.md` states the activation gate before workflow
  instructions. Its Codex default prompt invokes the exact `$skill-name`.
- Codex's `agents/openai.yaml` sets `policy.allow_implicit_invocation: false`
  for `ui-implementation-audit`; its shared `SKILL.md` sets Claude Code's
  `disable-model-invocation: true`. Deterministic self-tests reject either
  missing native gate or a Codex entry prompt that does not name the skill.
- Applicability remains a second gate after invocation. Explicitly invoking the
  implemented-UI audit does not bypass its requirement for a substantive,
  repo-owned executable UI surface.

### Alternatives and boundaries

- Narrower trigger prose alone was rejected because it still permits semantic
  matching and keeps the workflow implicitly eligible.
- An applicability-only gate was rejected because checking eligibility already
  begins an unrequested heavy workflow.
- Removing or disabling the skill entirely was rejected because deliberate
  audits remain useful.
- Focused UI verification and ordinary UI review remain available without this
  exhaustive audit. This decision controls activation, not audit scope after a
  valid invocation.

### Sources and compatibility

- OpenAI's [Build skills](https://learn.chatgpt.com/docs/build-skills.md)
  documentation defines `agents/openai.yaml` policy
  `allow_implicit_invocation: false` and preserves explicit `$skill`
  invocation.
- Anthropic's [Claude Code skills](https://code.claude.com/docs/en/slash-commands)
  documentation defines top-level `disable-model-invocation: true`, which
  removes the skill from Claude's model-visible listing until the user invokes
  `/skill-name`.
- The Claude field is a deliberate vendor extension to the shared `SKILL.md`;
  it does not replace Codex's separate metadata. Repository self-tests validate
  both native gates because a generic single-runtime frontmatter validator does
  not establish dual-runtime behavior.

This decision extends D-20260731-01's explicit-only activation principle to the
implemented-UI audit without changing the two full-repository audit skills.
