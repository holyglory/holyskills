# D-20260801-02 — Hook installation is a portable orchestration skill

Index: [DecisionHistory.md](../DecisionHistory.md)

## Detail

### Objective

Users of a HolySkills checkout need one discoverable workflow that can inspect
their actual Codex and Claude Code installations, install missing requested
prerequisites, deploy the shared delivery-efficiency hooks transactionally,
activate what each host permits, and prove that new tasks are correlated with
provider usage. Repeating the README procedure manually left runtime-home,
restart, trust, and fresh-evidence steps easy to omit.

### Selected boundary

- `skills/install-delivery-efficiency-hooks/` owns only orchestration guidance
  and a bounded activation-status receipt.
- `tools/delivery-efficiency/` remains the sole implementation of the runtime,
  schema, privacy allowlist, store, hook translators, installer, and rollback.
- The skill invokes the recorder's digest-reviewed plan/apply/verify workflow;
  it never hand-edits generated runtime files or creates a second ledger writer.
- Every Codex and Claude home is explicit. Native Windows and WSL remain
  separate installations and stores, and WSL state stays on its Linux
  filesystem.

### Activation and trust

- The workflow may enable Codex's stable `hooks` feature for the exact requested
  home when the user requested activation and no higher-precedence policy blocks
  it.
- Filesystem installation does not prove activation. Each configured runtime
  must fully restart and produce a new hook-created task plus task-bound usage
  after a captured sequence baseline.
- Codex hook trust remains an operator action through `/hooks`. The skill must
  not edit a trust store or retain a hook-trust bypass. Claude settings are
  verified through the host's own status and hooks surfaces when precedence is
  uncertain.
- Recorder installation or retirement, feature and trust changes, and
  credential generation or rotation use the project-specific security-
  assumption gate. Credential rotation is never inferred from a version bump.
- Recorder rollback restores only journal-owned actions. A Codex feature state
  changed before planning is recorded and, on whole-workflow rollback, restored
  separately only from a confirmed prior state.
- Runtime authentication, trust, hook health, or telemetry status never grants
  authority beyond the user's installation request.

### Portability and evidence

The skill supports macOS, Linux, native Windows, and WSL with Python 3.9 or
newer and current supported Codex/Claude installations. Its platform reference
routes missing software to current official installation sources rather than
embedding remote bootstrap commands that can age invisibly. Its helper emits
only bounded allowlisted counts and sequences; raw telemetry remains in cold
per-user state outside model context and source worktrees.

Repository validation treats this as the sixth independently installable skill
and tests it both in place and from a standalone copy. Native platform claims
remain distinct from simulated path tests and require their respective CI jobs.
