# D-20260805-01 — UI copy is concise and nonredundant by default

Index: [DecisionHistory.md](../DecisionHistory.md)

## Detail

### Evidence and objective

The user supplied an explicit universal UI-copy rule after agents added subtitles, helper text, and
descriptions beneath otherwise clear headings, labels, cards, and settings. The objective is a quieter
interface in which supporting copy exists only when it prevents a real comprehension or error risk.

### Selected behavior

- Prefer one concise, self-explanatory heading or label.
- Do not add subtitles, helper text, or descriptive copy beneath headings, labels, cards, or settings
  by default.
- Add supporting copy only when the user explicitly requests it or it is necessary to prevent
  misunderstanding or error.
- Supporting copy adds information; it never restates its heading or label.
- Review the agreed screens and responsive variants for redundant subordinate copy while preserving
  necessary instructions, warnings, validation guidance, and requested explanation.

### Alternatives and boundaries

- Automatic descriptions were rejected because they repeat obvious labels and weaken hierarchy.
- A total ban was rejected because unfamiliar concepts, consequential actions, validation, and error
  prevention can require concise supporting information.
- This rule changes copy defaults, not the agreed feature set or the explicit-only audit boundary.

### Verification

The universal-policy checker requires the concise-label default and both supporting-copy exceptions.
Its self-test rejects blanket descriptions, helper text on every setting, and heading restatement,
while accepting explicitly requested or error-preventing copy that adds new information.
