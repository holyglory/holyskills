# D-20260805-02 — In-scope browser QA and runtime coordination have standing permission

Index: [DecisionHistory.md](../DecisionHistory.md)

## Detail

### Evidence and objective

The user reported that agents repeatedly asked for explicit authorization before using Playwright
and the configured DevCoordinator. Those prompts slowed ordinary implementation and verification
even when tool use was already relevant to the agreed task.

### Selected behavior

- The instruction is standing and applies across repositories.
- Invoke Playwright or equivalent browser automation directly for in-scope local preview,
  reproduction, rendered interaction testing, evidence capture, and browser QA.
- Use the configured DevCoordinator for relevant in-scope local service, port, health, log,
  telemetry, test, and temporary-runtime lifecycle work.
- Do not ask for another chat authorization before those routine invocations.

### Boundaries

The standing permission authorizes use of those tools only within the agreed task and their
documented controls. It does not expand scope; authorize production changes, destructive data work,
credential or trust changes; bypass host or tool approvals; waive security-assumption, backup,
recovery, or coordination gates; or replace informed approval for a material unrequested expansion.

### Verification

The universal-policy checker requires the standing permission and its safety boundary. Its self-test
rejects repeat authorization requirements for in-scope Playwright and DevCoordinator use while
accepting approval gates for materially different actions.
