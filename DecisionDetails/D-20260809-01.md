# D-20260809-01 — Remote Codex handoff owns the persistent app-server boundary

Index: [DecisionHistory.md](../DecisionHistory.md)

## Detail

### Context

The first `holygloryTT` deferred install waited for every captured Codex process.
Quitting the macOS client removed the remote proxy but not the Linux app-server
or its helper, which are intentionally durable. The job remained unapplied and
the agent redirected the user to SSH, violating the zero-Terminal product goal.

### Selected behavior

Recorder `0.2.7` binds one reviewed target name and home to exact transient
clients/proxies, app-server daemon, owned helpers, executable identity,
CLI/app-server versions, lifecycle backend, and required bootstrap features.
It waits for transient connections first and rechecks every binding before
freezing cancellation and the user-wait deadline.

A reported nonempty backend selects the exact captured executable's native
`app-server daemon stop` with a fixed platform system path. A running response
without `backend` is legacy, not native-control proof. On Linux only, the
worker may open a pidfd for the exact reviewed process, recheck its complete
identity, and send graceful `SIGTERM` through that pidfd—never a bare-PID
signal or `SIGKILL`. After the bound daemon and helpers exit, it invokes the
exact Codex executable's bootstrap with explicit reviewed features, requires a
real backend, and invokes native stop before transactional apply/verify. The
macOS remote workflow explicitly preserves `code_mode_host`.

Current code may observe or cancel explicitly allowlisted `0.2.4` through
`0.2.6` deferred jobs, but its mutation validator rejects their recorder
version.

### Alternatives and evidence

Passive waiting failed on the real persistent topology. User-run SSH moves
lifecycle ownership to the user. A bare-PID signal or `SIGKILL` weakens identity
and shutdown guarantees. Applying while the daemon is live risks stale
host-loaded settings. A privileged persistent installer adds unnecessary
authority. Pure native stop works only when Codex reports a backend; the live
macOS-remote legacy server does not. The selected split uses Codex-native
lifecycle wherever it exists and the narrow Linux pidfd bridge only to move
the exact reviewed legacy process into that lifecycle.

### Verification


The first live native-stop attempt failed unapplied because its minimal
environment omitted the fixed path Codex 0.147.0 needs for `ps`. The next
attempt also failed unapplied because a responsive legacy socket was mistaken
for a managed backend. The real daemon's version response has no `backend`,
and Codex bootstrap refuses to adopt it while it runs. This matches the remote
app-server lifecycle reported in OpenAI Codex issue #24542.

Focused tests cover missing-backend classification, Linux pidfd-only graceful
termination, exact identity rechecks, explicit `code_mode_host`, bootstrap
backend proof, native stop, proxy-first ordering, fixed-system-path behavior,
drift and failure guards, historical observation-only compatibility, receipt
privacy, and unaffected ordinary installs. Platform-native Windows, WSL, and
broader Linux evidence remains tracked separately in `CompletionLedger.md`.
