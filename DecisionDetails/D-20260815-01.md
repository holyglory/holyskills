# D-20260815-01 — VPS development accounts share repository access

Index: [DecisionHistory.md](../DecisionHistory.md)

## Detail

### Scope

The user confirmed that `holyglory`, `holygloryTT`, `slawa`, and `axel` are
four workspaces of the same human operator on one development VPS. This
decision covers valid Git working trees, linked worktrees, metadata, and bare
repositories under `/home`. It excludes service/system accounts and does not
make unrelated home-directory content readable or writable.

### Selected implementation

- Maintain `vps-repo-users` with the four confirmed accounts.
- Apply named-user and named-group read/write/traverse ACLs recursively to each
  repository-associated `.git` marker root, including incomplete marker roots,
  with default ACLs on repository directories so new content inherits access
  immediately—even for sessions started before group membership refreshes.
- Grant traverse-only ACLs on necessary ancestors.
- Configure `core.sharedRepository=group` in each valid repository.
- Add exact repository paths to each account's global `safe.directory` list;
  do not use `safe.directory=*`.
- Preserve separate per-account recorder state, credentials, and counters.

### Evidence and maintenance

Discovery found 46 `.git`-named markers under `/home`; Git validation identified
19 usable repositories and 27 incomplete cache/workspace markers. ACL sharing
covers all marker roots, while only the 19 valid repositories receive Git trust
and shared-repository configuration. Access verification exercises Git discovery
and temporary cross-account file creation, modification, and removal in every
valid repository, validates inherited ACLs across all marker roots, then confirms
cleanup.

New repositories outside an existing shared root need the same exact ACL and
safe-directory enrollment. Revisit the decision if the VPS gains another human
operator, an untrusted account, repositories outside `/home`, or a need to
share non-repository home data.
