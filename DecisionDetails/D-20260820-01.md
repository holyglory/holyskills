# D-20260820-01 — Completion history is database-only

Index: [DecisionHistory.md](../DecisionHistory.md)

## Detail

### User correction

The user clarified that the Completion Ledger is software- and database-owned
and directed that every skill and `AGENTS.md` instruction follow that concept.
The prior compatibility rule still allowed an open-only
`CompletionLedger.md`, and `full-repo-audit` still advertised and implemented a
Markdown plan/apply workflow. Those instructions could split unfinished work
between incompatible stores.

### Selected contract

Every repository uses one authoritative database work graph and Completion
Ledger. The database owns issue creation, transactional import, state changes,
release moves, implementation, verification, reopening, supersession, and
permanent event history. Agents normally query only active not-implemented work
or one named issue's bounded history. They never create, update, import through,
or fall back to `CompletionLedger.md`, a checklist, another archive, or chat
memory.

The default portable implementation binds the Git common-directory identity
and stores shared state at the primary checkout's ignored
`.product-delivery/delivery.sqlite3`. Linked worktrees and the four trusted
`holyglory`, `holygloryTT`, `axel`, and `slawa` accounts therefore use the same
database. Its parent inherits repository ACLs and the database is owner/group
writable; non-owner trusted accounts do not need to change its mode.

### Migration

The nine active Markdown rows `Q-5`, `Q-7`, `Q-8`, `Q-9`, `Q-13`, `Q-15`,
`Q-16`, `Q-17`, and `Q-18` were parsed through the former canonical row parser
and applied once through import
`holyskills-markdown-ledger-migration-20260820`. The database recorded import
digest `6b300ec208529249ffd7afa766323afb33094bd109d31dc3569d233c83486ab0`,
one permanent event per issue, original status and verification text as
metadata, and an idempotent exact replay. The Markdown file was then removed.

### Audit integration

`full-repo-audit` continues to verify and reconcile all findings outside the
audited repository. Its active workflow now converts the fully reviewed
projection into `holyskills.completion-ledger-import.v1`, bound to the audit
evidence and a stable import ID. `coordinate-product-delivery` validates the
whole payload and all references before one transaction, stores its digest,
rejects changed content under a reused ID, and treats exact replay as already
applied. Missing database capability leaves the import unapplied and visible;
it never permits a file fallback.

### Verification expectation

Deterministic policy tests reject Markdown-ledger authority, mutation, and
fallback language. The repository ledger checker rejects any
`CompletionLedger.md` object and can verify the live SQLite schema, required
tables, permanence triggers, and integrity. Skill tests prove shared default
location, transactional import, idempotent replay, changed-content refusal,
permanent issues, and release gates. Complete validation scans both
`AGENTS.md` files and canonical skill instructions for contradictory active
directions.
