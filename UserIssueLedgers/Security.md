# User Issue Ledger: Security

| ID | Applies to | Mistake pattern | Required behavior | Prevention and verification |
| --- | --- | --- | --- | --- |
| UIL-SECURITY-001 | Decisions that add, change, weaken, remove, or intentionally omit security-posture controls | Agents applied generic maximum-hardening measures without establishing who uses the software, its operating environment, credible threats and trust boundaries, or which gates were necessary versus irrelevant. | Base every security-posture decision on project-specific, user-confirmed assumptions recorded in project-root `security-assumptions.md`. If the file is absent, question the user about the full baseline—users and operators, environment and ownership, assets and data sensitivity, credible adversaries and misuse, trust boundaries, required gates, explicitly unnecessary gates, acceptable risks, and review triggers—and document confirmed answers before implementation. If it is insufficient, ask only the unresolved material questions. Record unknowns explicitly; they cannot justify a control. Never invent assumptions or default to maximum hardening. | Require the security-assumption gate and file contract in universal policy; add must-catch fixtures for absent or unconfirmed assumptions, inferred threats, unconditional hardening, and weakened/removed/omitted controls plus false-positive guards for non-security work, read-only discovery, and assumption-backed proportional controls; verify each implemented security-posture decision cites its supporting assumptions. |
