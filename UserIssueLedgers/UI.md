# User Issue Ledger: UI

| ID | Applies to | Mistake pattern | Required behavior | Prevention and verification |
| --- | --- | --- | --- | --- |
| UIL-UI-001 | Product UI implementation and completion claims | Agents delivered visible enabled controls that were inert, simulated, only partially wired, or verified by routes, rendering, screenshots, or geometry without exercising the promised interaction. | Every visible enabled control must perform its stated action end to end and produce the expected observable result through the rendered interface. Mock-data prototypes may use synthetic data, but their visible interactions must work truthfully within the declared prototype boundary. Unimplemented agreed behavior remains an explicit, control-specific `CompletionLedger.md` item and blocks completion; a specification-required future control is semantically disabled, visibly unavailable, and tracked there, while out-of-scope future information is noninteractive content rather than a control. | Before UI completion, inventory every visible interactive element across only the agreed screens, journeys, states, and responsive variants; map it to its journey and observable result; exercise applicable success, cancellation, validation, permission-failure, recovery, and persistence paths; batch-record and fix gaps; and require zero behaviorless enabled controls, zero requested journeys without rendered end-to-end evidence, and zero request-related completion-ledger entries. Enforce direct skip, representative-subset, catch-all-ledger, clickable-future-control, and static-sufficiency must-catch variants plus negative-phrasing precision guards, without implicitly authorizing a broader audit. |
| UIL-UI-002 | Headings, labels, cards, settings, and their supporting copy | Agents added subtitles, helper text, or descriptive copy by default, often restating a clear heading or label and making the interface verbose. | Prefer one concise, self-explanatory heading or label. Add supporting copy only when the user explicitly requests it or it is necessary to prevent misunderstanding or error; never use it to restate the heading or label. | Review subordinate UI copy across the agreed screens and variants; remove default or redundant descriptions while preserving necessary instructions and warnings. Enforce must-catch fixtures for prefix/default/blanket copy, discretionary “helpful” descriptions, and restatement by repeat, paraphrase, or echo; independently guard explicit-request, error-prevention, and negative-quantifier phrasing from false positives. |
| UIL-UI-003 | Data-backed UI content and completion claims | Agents inserted made-up numbers, parameters, statuses, or results so a product screen looked populated, then left the real data source, processing, or persistence unfinished and untracked. | Production UI presents factual values only from a real source, user input, measurement, imported data, or an explicitly requested deterministic definition. If agreed data is unavailable, show an honest loading, error, empty, or unavailable state and keep the missing integration in `CompletionLedger.md`; do not substitute plausible demo values. Synthetic content remains isolated to an explicitly declared design, test, or mock-data prototype and is never presented as production behavior. | Enforce truthful-data policy terms and must-catch fixtures for plausible invented metrics, parameters, and results plus an unledgered missing integration. Preserve passing fixtures for clearly declared test/design examples and honest unavailable states. Verify the rendered production path against its real data source and require no request-related ledger item before completion. |
